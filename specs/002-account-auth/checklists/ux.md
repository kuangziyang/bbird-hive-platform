# UX 需求质量清单：账号认证与平台角色

**目的**：检验 UX 相关需求是否清晰、完整、可测、覆盖边界场景
**对应规格**：[spec.md](../spec.md) §用户场景 1-4、§边界情况
**生成时间**：2026-06-05

## 登录流程可发现性

- [ ] CHK001 - 登录入口的位置与可发现性是否在普通用户和管理员路径上都有明确规定？[Coverage, Spec §US1]
- [ ] CHK002 - 用户名和密码输入框的标签、占位符、可见性切换是否有一致约束？[Consistency, Gap]
- [ ] CHK003 - 「忘记密码」「修改密码」入口是否对普通用户和管理员分别定义？[Completeness, Spec §US4]
- [ ] CHK004 - 登录失败时的错误信息粒度（用户名错 / 密码错 / 账号停用）是否在需求中明确？[Clarity, Spec §US1 验收 3]

## 初始密码展示

- [ ] CHK005 - 管理员创建账号后展示初始密码的视觉强调（一次性告警、复制按钮、确认已转交）是否被规格化？[Clarity, Spec §US3 验收 1 + §边界]
- [ ] CHK006 - 管理员重置密码后展示新密码的 UX 与创建时是否一致？[Consistency, Spec §US4 验收 2 + §边界]
- [ ] CHK007 - 「初始密码只在创建/重置时展示一次」是否同时定义了刷新页面后是否消失？[Edge Case, Gap]

## 错误与可访问性

- [ ] CHK009 - 键盘可访问性（Tab 顺序、Enter 提交、Esc 关闭对话框）是否在登录、改密、初始密码展示三处明确？[Coverage, Gap]
- [ ] CHK010 - 屏幕阅读器对错误提示的可达性（aria-live / role="alert"）是否被规格化？[Coverage, Gap]
